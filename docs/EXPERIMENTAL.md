# 道路实验版 1.6.3 — 独立测试说明

本工程从稳定版1.5.1复制，位于“05_道路实验”，未修改或合入“04_拖拽式重制”稳定工程。稳定版JAR的SHA256已核对保持不变。

## 安装与使用

1. 复制测试存档/启动配置，在复制的环境中测试。移除该配置里的稳定版同模组JAR，放入本目录的 tlm-flow-maid-road-experimental-1.6.3.jar；两者使用相同modId，不能同时安装。服务器和客户端都须使用实验版，网络版本与稳定版不同。
2. 给女仆准备圆石，并将适合障碍方块的工具放在主手。只有圆石会用于搭路，不凭空生成材料。
3. 点击流程图上方独立“设置”按钮，在“通用移动”分类打开“所有流程动作的筑路 / 拆障”。这是当前主人在本存档内跨女仆、跨流程共享的开关，默认关闭；旧移动节点上的实验开关不再生效。无需给每张动作卡片设置。开启后移动到主人也先走通用寻路/筑路；关闭时保留原来的移动到主人失败传送。
4. 普通寻路三次失败/无进展后，才开始局部道路规划。能正常绕行就正常走，不为了展示功能强行修路。
5. 仅搭路时自动消耗圆石；涉及拆障时，主人收到窗口，逐页列出本次将破坏的方块坐标和类型、搭建数量及维度。允许或拒绝只对这次规划有效，Esc为拒绝。
6. 许可最多有效2分钟。本次规划中的多个方块不逐块弹窗；重新规划、过期、任务切换/取消、保存恢复后都不能沿用旧许可。方块或禁拆规则发生变化时终止，不按旧许可拆新对象。

## 禁拆保护

独立“设置 → 禁拆区域”提供“对角点一/二”。用准星点选两块方块后，点击“保存两点之间的全高度禁拆区”。其X/Z矩形范围包含边界，Y从世界底部到顶部全部受保护。

“设置 → 禁拆方块”的输入框支持中文联想，选中后点击添加。规则属于当前所有者，跨其女仆和任务共享，存入世界SavedData，独立于女仆死亡与任务库；区域按维度区分，方块类型禁用对所有维度生效。保存后聊天提示已有区域数和方块类型数。

清空某一类别的保护须在5秒内点击同一清空按钮两次。既有许可不能覆盖后来新增的保护。保护也接入母模组的 LivingDestroyBlockEvent，因此走母模组正常破坏钩子的采集不能绕过禁拆区；不承诺能拦截其他模组完全绕开事件直接修改世界的行为。

## 本次原型的明确边界

- 只探索女仆起点水平各16格、垂直各6格的局部范围；最多24步、48个改动位置。更长或复杂的道路会停止提示，不保证任意地形一定有方案。
- 每tick最多96个搜索节点，总计最多4096个，不加载新区域、不阻塞tick等待结果。
- 避开液体、不可破坏方块、下落方块及其邻接风险；容器/方块实体、门、床、双高方块、TNT不自动拆除。
- 只在空气处放圆石，不覆盖已有方块；操作前复查世界状态、保护权限、工具、触及距离、视线、mobGriefing与Forge放置/破坏事件。保护模组取消放置时恢复方块并退还圆石。
- 工具消耗耐久；拆下资源走女仆资源入包链路。缺圆石、工具不合适、施工后仍走不过去等会停止并提示。当前原型不保证缺料后自动改选另一条方案，补齐后可重新运行。
- 已经建成的道路、已经批准并完成的拆障不会因后续失败自动回滚，避免再次改动玩家后来使用的空间。因此请使用复制的测试存档。
- 施工规划、许可不写入永久执行数据；重进世界不会恢复批准状态，必须重新规划和申请。

## 建议游戏端验收

A. 在平台中间做两格宽、至少四格深的缺口，给女仆足够圆石，移动到另一侧：观察三次失败后搭路，圆石应减少且女仆实际走过去。

B. 在两侧不能绕行、顶部不能跨越的走廊放两格高石墙，主手给镐：未批准前墙不应变化；拒绝后应停止；重新运行并允许一次，墙内多个批准方块可以继续拆除，不反复逐块问。

C. 把石墙所在列设为禁拆区域，或把石头加入禁拆类型：即使先前批准过，也不应再拆。检查高于/低于两点所选Y的同列方块也受保护。

D. 审批窗口出现后，手动把某个待拆石头换成其他方块，再允许：旧规划应作废，不能自动拆换进去的新方块。取消任务/更换工作后旧审批不能继续生效。

## 1.6.2 通用层调整

- 移动、取物、存物、采集、攻击/巡逻追踪、喂养/繁殖接近目标均走共享移动或工作站位入口。找不到可达工作站位时，也会在三轮尝试后进入道路规划，避免提前跳过筑路。
- “调用女仆工作”监测原生工作发出的WALK_TARGET移动记忆。连续三次无法规划路径后调用同一施工器；施工期间临时暂停原生工作模式，完成后恢复原工作及流程进度，避免两套AI争抢移动。第三方工作若完全绕开该移动记忆直接操控位置，尚不能保证自动接管，需要专用适配；本功能不接管流程之外随意选择的普通原生工作。
- 开关与保护属于主人的世界设置；箭头避让和排列规则移入“设置 → 流程图”，仍随当前任务保存。自动整理与撤销整理保留在地图工具栏。
- 在设置页和世界点选期间保持编辑暂停状态，返回编辑器不丢失节点选择、视野和未提交参数。禁拆区域、方块类型均可独立清空，仍需双击确认。
- 关闭全局开关会终止进行中的道路施工；拒绝、过期、缺工具/材料或无安全局部方案会停止当前流程，不会无限重试拆路。已经完成的地形改动不会回滚。

新增验收：不放移动节点，分别直接连接开始→取物/存物/采集→结束，在目标前加不可绕行石墙，观察申请、真实移动以及之后的实际工作；检查喂养、繁殖和攻击接近目标也使用同一开关。原生工作测试目前验证标准移动记忆接入、施工暂停及恢复，不等同于所有第三方工作均已实测。

## 1.6.2 悬空矿物修复

1. 采集扫描由中心上下4格扩大为上下16格；仍然每tick最多探测128个已加载方块，不强制加载区块。中心点可以选地面，不必指定矿物本身坐标。
2. 矿物附近没有现成地面时，会寻找搭建后可站立、能看见且触及目标的工作位置，三次普通寻路/站位尝试失败后调用通用筑路。
3. 排除会把圆石放在女仆当前身体里的工作位置。阶梯规划也排除互相堵住的支撑块；重新规划须等女仆稳定落地，避免采用跳跃中途的临时位置。
4. 每一施工步必须真正落地并靠近台阶中心才算完成；规划、等待审批、搭建、拆障和步间停顿时清理残留行走目标及水平惯性，防止搭下一阶时自己走下台阶。
5. 施工失败提示包含失败步和女仆位置，便于后续游戏端定位。

新增服务端用例：平地中心上方悬空放置4块矿物（最低比女仆初始脚部高6格），给真实圆石和镐；不使用传送或测试脚本移动女仆，验证实际搭阶梯、爬高、消耗圆石并采完4块矿物，流程正常结束。完整52项必需GameTest通过。

本轮调试中复现并修复了跳跃中途误判到达、施工停顿时残留行走以及选择自身上方无法搭建的站位等故障。一次完整回归还出现既有攻击测试的距离断言失败，后续最终完整回归通过；该偶发测试波动留档，不据此宣称攻击兼容性已全部实测。

## 1.6.3 减速与窄路防跌落

- 流程任务和流程调用的原生工作加入服务端物理移动限制：一般地面水平移动上限0.16格/tick（20TPS时约3.2格/秒），边缘0.08格/tick，空中0.12格/tick。数值是上限，不是恒定速度。
- 移动前检查脚下预测支撑，主动走向超过一格的落差时缩短水平步幅，避免中心越出支撑面。保留重力、真实跳跃与正常单格下台阶；不传送、不锁定高度。
- 施工路线降低移动控制速度，沿已规划的相邻台阶中心逐格走，避免原生导航斜切转角跨过空气。每段开始先居中，落地居中后才继续；转角起跳前先对正方向并清除水平惯性，临近落点刹车。
- 新物理钩子只处理服务端已启动流程女仆的SELF移动；普通女仆、未运行流程、骑乘、水中和鞘翅飞行不受该限制，活塞推动不拦截。外力、复杂碰撞和其他模组直接修改位置仍不能保证绝不跌落。
- 默认启用减速与边缘保护，无须另开开关。通用筑路开关、材料和拆障许可规则不变。
